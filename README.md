# InvoiceIQ - интеллектуальная обработка счетов и заказов

---

## 1. Что за система и для кого

**InvoiceIQ** - сервис, который "читает" счет или заказ вместо человека.
Пользователь загружает PDF или скан, а система:

1. достает главные данные документа (номер, даты, поставщик, покупатель, суммы, валюта)
2. достает таблицу товаров и услуг (позиции)
3. приводит даты, суммы и валюты к одному виду
4. проверяет арифметику и показывает, где цифры не сходятся

**Для кого:** бухгалтеры и небольшие компании, которые вручную переписывают счета. Также может подойти разработчикам, которые хотят встроить такое распознавание в свои сервисы.

## 2. Какую проблему решает и как им пользуются

**Проблема.** Счета приходят от множества поставщиков, и у каждого свой макет. Ручной ввод медленный,
скучный и дает ошибки (перепутаная дата, лишний ноль, чистая сумма вместо суммы с налогом и т.д.).
Ошибки в арифметике самого счета тоже часто проходят незамеченными.

**Как пользуются:** Загрузить файл -> Посмотреть результат (поля документа, таблица позиций, отчет проверок) -> Исправить спорные поля -> Выгрузить JSON

### Какие поля достает

Поля сделаны примерно как из разметки DocILE.

| Группа | Поля | Пример нормализации |
|---|---|---|
| Документ | `document_id` (номер), `order_id` (номер заказа), `date_issue`, `date_due` | `03/04/2023` -> `2023-03-04` |
| Поставщик | `vendor_name`, `vendor_address`, `vendor_tax_id` | обрезка пробелов, единый регистр |
| Покупатель | `customer_bill_name`, `customer_bill_address` | обрезка пробелов, единый регистр |
| Суммы | `amount_total_net`, `amount_total_tax`, `amount_total_gross` | `1.234,50 €` -> `1234.50` |
| Валюта | `currency_code` | `€`, `EUR`, `euro` -> `EUR` |
| Условия | `payment_terms` | ? |
| Позиции (n строк таблицы) | `description`, `code`, `quantity`, `unit_price`, `tax_rate`, `amount_net`, `amount_gross` | `5 шт.` -> `5`; `20 %` -> `0.20` |

Нейросеть находит числа, а алгоритм их пересчитывает.

| Проверка | Что сравнить | Допуск |

## 5. Данные

[DocILE](https://docile.rossum.ai/) - открытый бенчмарк от Rossum для двух задач: KILE (Key Information Localization and Extraction) и LIR (Line Item Recognition).

В нем находятся:
1. размеченные документы - ~6,7 тыс (train / val / test) (нужны для обучения/дообучения и честной оценки)
2. синтетические документы - 100 тыс (можно использовать для дообучения и большего разнообразия) 
3. неразмеченные документы - ~1 млн (вряд ли понадобится)

Все документы относятся к категории полуструктурированных деловых бумаг, таких как счета-фактуры,
заказы на покупку, квитанции, кредит-ноты и другие подобные финансовые документы.

Также в бенчмарке имеется готовый OCR (DocTR), что позволяет не запускать OCR самостоятельно.

**Доп. источники**, которые в теории можно использовать: [Kaggle](https://www.kaggle.com/datasets/ayoubcherguelaine/company-documents-dataset/) - коллекция 2000+ документов компании, разделенных на четыре основных типа: счета-фактуры, отчеты о запасах, заказы на покупку и заказы на отгрузку.

## 6. Как планируешь решать задачу

### Архитектура (конвейер)

1. Подготовка: страницы -> изображение, выравнивание, определение того, есть ли текстовый слой в PDF (тогда OCR не нужен)
2. Извлечение полей и таблицы: ВАРИАНТ A: OCR + модель или ВАРИАНТ B: мультимодальная LLM (видит картинку, отвечает JSON) -> поля документа + строки таблицы
3. Нормализация: даты -> ISO, суммы -> числа, валюта -> код, проверка по схеме (типы, обязательные поля)
4. Проверки: арифметика и логика (алгоритмами) -> ok / warn / fail
5. Выдача: JSON по API или веб-интерфейс с подсветкой спорных полей на картинке

ОБЯЗАТЕЛЬНО: ML только там, где без него нельзя (понять, где на странице номер счета и
где таблица). Нормализация и проверки - обычный алго код.
